## Reproduce host predictions

```bash
for f in good malicious wrong-key tamper raw wrong-platform downgrade trunc-sig forged-size; do
  python3 Phase_14/tools/attack_bundle.py verify Phase_14/attacks/$f.bin
done
```

## Board-side procedure (once hardware is attached)

1. Mount FAT32 SD, run `restore_good.sh`, copy `good.bin` to `seedsigner_esp32p4.bin`, boot → baseline.
2. For each of T4..T10: copy the bundle to SD as `seedsigner_esp32p4.bin`, `capture_log.sh <tag>`.
3. T1/T3: build `build_wrong_key_loader.sh` (wrong-key loader) or strip the good loader's
   last 4 KB (sig block); flash @0x30000 with `esptool.py write_flash`, expect SBv2 rejection +
   reboot loop, then `restore_good.sh`.
4. T11/T12/T13: flash-level attacks via `esptool.py` (byte-flip random_fill / nvs digest, erase nvs),
   see campaign section of the master doc.
5. `restore_good.sh` to return to the good baseline between tests.
